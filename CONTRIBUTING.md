# Contributing to Awesome Harness

Thank you for contributing. This list is about **harness engineering** - the environment around the model, not the model itself. Keep that boundary in mind when proposing entries.

## What belongs here

- Articles, papers, or blog posts that address a **specific harness problem** with technical substance
- Open-source projects that solve a real harness challenge (context, tools, sandboxing, evals, observability, guardrails, orchestration)
- Reference implementations where the harness design is directly readable and learnable

## What doesn't belong

- Generic LLM introductions or overview articles
- Proprietary/closed-source tools with no inspectable design
- Marketing content or product announcements without technical depth
- Redundant entries that say the same thing as an existing entry (prefer the more primary/practical one)

## Format

Each entry should follow this format:

```
- [Title](url) - One sentence explaining *why* this matters for harness engineering, not just what it is.
```

The annotation is mandatory. "A tool for X" is not enough - explain what specific harness problem it solves or what insight it provides.

## Process

1. Fork the repo
2. Add your entry under the correct section in `README.md`
3. Open a pull request with a brief description of what you're adding and why

If you're unsure which section fits, open an issue first.
